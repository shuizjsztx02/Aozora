# Aozora · 安全基线

- Android 禁止明文流量和系统备份。
- WebView 禁止 file/content access，JS Bridge 仅按版本化白名单增加。
- 签名密钥、服务商密钥、数据库连接和环境文件不得提交；仅通过外部密钥存储注入。
- 业务日志使用结构化、脱敏字段，禁止记录 token、原始票据和账本明细。
- **会话事件日志（M7 起，`D-PROD-13` 明确例外）**：可按保留策略存储**完整对话内容**——这是账户所有者基于 agent 效果优先所做的决策，见 `docs/adr/ADR-007-deepseek-provider.md` 决策 3。约束条件（缺一不可）：保留期对齐 `D-PROD-08`（请求后立即冻结、7 天内完成物理删除）；登出 / 删号联动清理；读取面带用户归属校验，跨用户返回 404。**该例外仅限会话事件日志**——上面「业务日志禁止记录完整对话」的脱敏要求不变，两者不是同一存储面。保留期的落地形态、数值与访问面审计结论见本文末「会话事件日志的保留期」。

> **修订记录（2026-09-18）：** 原条款为「禁止记录 token、**完整对话**、原始票据和账本明细」，其中「完整对话」一项由绝对禁令改为上述有条件例外。动因：M7 P3 的会话事件日志需保留完整对话以实现断连恢复、分叉与审计（架构 §6.2），与服务端 loop 的可靠性目标直接相关。token / 原始票据 / 账本明细三项**仍为绝对禁令**。风险侧记录见 `docs/risk-register.md` R-PROD-20。

已暴露的服务商密钥必须在外部控制台撤销或轮换后，才允许分发任何构建产物。

## 附件上传与存储面（T-M4-04c）

附件上传是服务端直接面向用户文件的攻击面，需关注以下约束：

| 维度 | 措施 |
|---|---|
| **大小** | 单文件上限 10 MB；分块读取（64 KB/块），累计超限即返回 413 中止，不全量缓冲（R-M4-41） |
| **MIME 防伪** | Content-Type header 与 magic-byte 嗅探双检；嗅探不识别 → 415 拒绝，不回退到 header（R-M4-40）。允许格式：`image/jpeg` `image/png` `image/webp` |
| **所有权** | 每行 `user_id` NOT NULL；读/写/下载/删除均强制归属校验，跨用户返回 404（不泄露存在性） |
| **存储路径** | 本地 `upload_dir`（默认 `/tmp/aozora_uploads`），POSIX 下 `0o700`；对象键 `<user_id>/<uuid>.<ext>` 兼容 S3（D-EXEC-05） |
| **生命周期** | PENDING 24h 自动过期；启动清理仅删 DB 中已过期行，绝不触碰 LINKED/PARSED 引用文件（R-M4-39） |
| **传输** | 客户端仅 HTTPS；服务端 CORS 白名单由 `CORS_ORIGIN` 环境变量控制 |

## 会话事件日志的保留期（T-M7-04d）

第 7 行那条有条件例外的**第一条约束**（「保留期对齐 `D-PROD-08`」）在 T-M7-04d 落地。
本节是该约束的**权威口径**：机制、数值、开关，以及读取面访问审计的结论。

| 维度 | 口径 |
|---|---|
| **窗口** | **30 天**——事件正文最多保留 30 天，到点由 retention 任务**物理删除**（初始值，`AI_CONVERSATION_RETENTION_DAYS` 可调；与 §6.3 的窗口 N=8、会话级双限同口径，真实使用分布出来后再校准） |
| **删除粒度** | **按整轮删**（一整轮 turn 的全部事件同进同出）。理由：§4.4 不变式 1（工具调用与结果配对）——按事件时间切会把「带 `tool_calls` 的 assistant 消息」与其 `tool` 结果切开，孤立结果会让下一轮模型请求 400。窗口边界落在轮中间时**整轮保留**（偏保守的方向） |
| **只删什么** | 只删 `ai_conversation_events` 的行。**不动 `ai_conversations` 行**（会话索引：标题 / 活跃时间）与 **`ai_usage` 行**（配额基座） |
| **为什么不动会话行** | 删会话行会让 `ai_usage.conversation_id` 按 `ON DELETE SET NULL` 置空，**会话级「轮数 + token」双限被清空**——用户只要等满一个保留期就能把会话配额刷回满额。这是 02f 用 `SET NULL` 防住的配额绕过，保留期不得把它重新打开。副产物：到期会话仍留在列表里（正文与模型上下文已无内容） |
| **为什么不动标题** | `title` 是用户自己首轮输入的 ≤40 字标签（列表上的会话名），不是「完整对话内容」；正文本体才是本例外允许存储、也受保留期约束的东西 |
| **开关** | `AI_CONVERSATION_RETENTION_ENABLED`，**默认关闭**，由部署侧显式开启（同 `RETENTION_JOB_ENABLED` 的口径）：`docker-compose.staging.yml` 与 `docker-compose.prod.yml` 均已置 `true`。**关闭即该约束不成立**——属部署缺陷，不是配置选项 |
| **运行形态** | 进程内任务（`server/src/modules/ai/retention.py` 的 `retention_loop`，随 API 生命周期启停），**不依赖 cron**；与遥测的 retention 任务不同，它**不**受 `ENABLE_TELEMETRY` 约束（隐私义务不该被埋点开关关掉） |

### 读取面访问审计：结论

**不新增读取面的审计记录——`security` 事件类型保持定义、不接生产者。** 三条理由：

1. **读取面的风险是跨用户泄漏，已由授权校验拦住。** 四个端点（列表 / 重命名 / 删除 / 事件增量读）一律带归属校验，别人的、已删除的、不存在的 id 返回**同一个 404**，不可分辨（02f 实现、03a 扩展到四个端点、本卡复审确认）；审计记录无法替代授权校验，只记录不拦等于没有防线。
2. **读路径不含新的隐私面，但会让日志自增。** 事件读端点是**客户端投影的重建源**（本地缓存丢失 / 断线补齐时调用），频次与用户正常使用同阶；把读取写进事件日志，日志会随读取自我放大，反而削弱保留期「有界」这个性质。而读取行为本身不改写任何对话内容。
3. **「谁在何时读了哪个会话」在 HTTP 层已有等价留痕。** `server/src/main.py` 的请求日志按**路由模板**记录（`/api/v1/ai/conversations/{conversation_id}/events`）+ status + `request_id`，既不落 conversation_id、也不落正文——满足本文第 6 行「业务日志脱敏」的不变部分。要把它升级成「可疑跨用户探测」告警，需要独立于业务事务的审计通道与阈值判定，那是另一个面（不是本约束的落地内容）。
