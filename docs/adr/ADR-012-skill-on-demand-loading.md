# ADR-012 域知识的按需加载（Skill）

**状态：** 已采纳（2026-09-20）
**范围：** M7 T-M7-05h（P4，批次 4；服务端侧，零客户端改动）
**关联文档：** `docs/architecture/ai-agent-architecture.md`（§6.4 Token 预算、§7.1 工具注册表、§7.2 域分组、§7.3 读工具与写工具）、`server/src/modules/ai/skills.py`、`server/tests/test_ai_skills.py`、`server/scripts/probe_skill_budget.py`、R-PROD-39

> **为什么需要一份 ADR：** 「按需加载」这句话里只有一处是不可逆的取舍——**加载条件**。选错时没有任何用例能从内部发现问题：域知识一旦常驻，系统提示只是变长，模型照样答得出来，代价只出现在账单与延迟上（而 P4 出口标准里的「Skill 不常驻上下文」正是一条**只能靠度量**验的条款）。与之同批被固定的还有两件事：预算用什么**单位**量（字符还是 token），以及超限时**截断还是整条丢**。这三件事会被后续每一张卡（新域、新能力、05j）依赖。

## 背景

### 三条影响结论的硬事实

| # | 事实 | 依据 |
|---|---|---|
| 1 | **工具 `description` 是模型可见的唯一语义来源**，且它只讲「这个工具能做什么」 | 架构 §7.1；`tools.py` 模块头。工具已到 **54 个 / 14 域** |
| 2 | **系统提示是每轮常驻的**（行为准则 + 日期 + 现有对象段），而记账 App 的绝大多数输入是「一句话记一笔」 | `agent._AGENT_SYSTEM_PROMPT`；PR-2 的 12 s / 25 s SLO 就在这条路上 |
| 3 | **域既是工具的分组单位、也是「这一轮在干什么」的最小可判定粒度**，而且注入面是一个**可观察量**：域路由（05g）收窄它、显式 `tools=` 覆盖它 | 架构 §7.2；`agent.AgentLoop._inject` |

### 问题的真正形态

工具全量化（05b–05d）之后，**跨工具的规则**没有落点：

- 写进某个工具的 `description` → 它讲的是**别的**工具的事。`scheduled_create` 的文案里写「以后每月自动记」时别用 `transaction_add`，既不属它，也会在下一个工具的文案里再重复一遍——两处会漂移的真相，而架构 §7.1 已经定过「description 自动生成后必须人工审核」，不该再多一个抄写面。
- 写进系统提示 → 它对**每一轮**都生效。绝大多数轮次根本用不到它（用户只是记一笔午饭），常驻的代价是每轮都要付的输入 token，且这个代价会随每一张新卡单调增长。

「新增一个表单能力不改 prompt 主体」（P4 出口标准）要的正是第三条路：**能力自己的那部分说话，放在能力自己的载荷里**。

## 备选方案

| 方案 | 内容 | 评估 |
|---|---|---|
| **A. 全写进工具 `description`** | 跨工具规则塞进其中一个工具的文案 | **否决。** 规则的主语是别的工具；且同一件事会在多个工具里各留一份（`scheduled` / `transaction` 两个域各写一遍），漂移只是时间问题 |
| **B. 全写进系统提示（常驻）** | 把域知识并进 `_AGENT_SYSTEM_PROMPT` | **否决。** 每一轮都付，而命中的轮次是少数；且它直接落在 PR-2 的快路径上（事实 2） |
| **C. 按域封装 + 按需注入**（**采纳**） | 一个 Skill 绑 1..N 个**工具域**，域命中才进系统提示；命中面来自「本轮的注入面」与「本轮实际用过的域」 | 成本只在该域真的进入本轮时付出；不命中时一个字都不加（可逐字取证）；零新依赖、零模型调用 |
| **D. 独立的「技能选择」模型调用** | 每轮先用一次轻量调用挑要加载哪些 Skill | **否决。** 与架构 §12.2 已定第 2 项否决轻量分类器**同一条理由**：给每一轮加一次模型调用，而这笔开销正好花在最不该花的地方（简单输入）；它自己也会错，还要再兜底一层 |

## 决策

### 决策 1：Skill 的形态——绑域的一段服务端文本，复用 `PromptTemplate` 作载体

```python
Skill(skill_id, domains: tuple[str, ...], title, template: PromptTemplate)
```

- **命中面是域**（不是关键词）：域是工具的分组单位，也是路由与注入面的既有粒度，因此「这一轮用得上它」不需要任何新的判定器。
- **可以绑多个域**：同一件事横跨两个域时（设备执行类规则横跨 `meta` / `persona`）只写一份——「不抄第二份」是本模块存在的理由本身。
- **正文装在 `PromptTemplate` 里**（`task_id` ＝ `skill.<id>`）：与 task 的 system prompt 是同一类东西（服务端持有、按 id 版本化、改它不用发版）。它**不会**被当成一次模型请求发出去，因此 `output_format` / `max_tokens` / `model` 三个字段在 Skill 上没有意义，没有任何代码读它们。
- **导入期校验**（域必须存在、id 不重复、正文非空且不超单条上限）：写错域的 Skill 是**永远不会命中**的，而「没命中」与「不存在」在运行期长得一模一样，只能当场炸。

### 决策 2：加载条件——两个来源取并集，**全量注入不算命中**

| 来源 | 规则 | 生效时机 | 为什么这样定 |
|---|---|---|---|
| **收窄的注入面**（前瞻式） | 本轮注入面若比**本车道**的全部域小，就带上这些域里有 Skill 的那些 | **第一个 Step 就在** | 注入面被收窄，说明「这一轮要做什么」已经有人认出来了（域路由，05g）；这时域知识与它同源，不必等模型先动手 |
| **实际用过的域**（懒加载） | 本轮有工具调用落在某域 → 带上它的域知识 | **下一个 Step 起** | 不依赖域路由的兜底：多步任务的第一步通常是查询，域知识恰好赶在第二步动手之前到位 |
| （全量注入） | **不带任何 Skill** | — | 「所有域都可能」等于没有命中。这时候加载就把域知识又变回了常驻——而那可是一条必须逐字取证的红线 |

两条都不命中时，系统提示与 05b–05d **逐字相同**（`_system_message` 在集合为空时不追加任何内容），由金标用例钉住。

**「本车道的全部域」而不是 `tools.DOMAINS`** 是这一条的关键：v1 车道上 `meta` 域一个工具都没有（它只有 `meta_set` 一个写工具，车道过滤后为空），拿 `DOMAINS` 比会把每一轮都误判成「收窄了」，域知识于是**每一轮都在**。

### 决策 3：预算——按**字符**量，单条 400 / 合计 1200，超限**整条不进**

- **单位是字符**：与 `prompts.py` 的所有注入段落同一把尺子（`_MAX_CONTEXT_TEXT_CHARS` / `AI_AGENT_SUMMARY_CHARS`），不另立 token 口径。真实 token 数由探针实测（见「后果」），但它不是**执行**这条上限的依据——服务端在渲染时拿不到 token（那要过一次分词器）。
- **超限整条丢弃**、后面的也不再进（先到先得，顺序＝注册表顺序）：与 04c 的摘要口径一致——半句规则比没有规则更误导（「不要用 `transaction_add`」被砍成「不要用」时语义正好反过来）。
- **单条上限在导入期拦**（写长了当场炸），运行期的合计上限只是兜底。

### 决策 4：位置与落库面

- 追加在**系统提示尾部**（摘要段之后、现有对象段之后）：它是最贴近这一轮的内容，且不改动既有段落的顺序与措辞。
- 只替换 `self._messages[0]`，**不进落库面**：系统消息不在 `_delta_start` 之后的增量里（P1 起就是这个形状），日志里永远没有 system 消息，因此本卡对事件日志、摘要、配额零影响。

## 后果

### 实测（2026-09-20，`deepseek-flash`，真实调用，`scripts/probe_skill_budget.py`）

| 臂 | 工具数 | 系统提示字符 | `prompt_tokens` |
|---|---|---|---|
| ① 全量注入 + 基础提示（现状） | 23 | 704 | 4888 |
| ② 全量注入 + 定时域知识 | 23 | 992 | 5032 |
| ③ 收窄注入（定时域）+ 域知识 | 1 | 992 | 879 |

- **域知识本身的成本：+144 tokens / 286 字符**（臂 ②−①；两臂工具载荷相同，故差值只含域知识）。
- **不命中：0**（未命中时一个字都不加，金标用例逐字钉住）。
- 臂 ③ 的 4888 → 879 是**域路由的收益**（少注入 22 个工具定义），与本卡的成本分开报——混在一个数字里说不清是谁的效果。

### 残余与责任人

1. **新域上线忘了写 Skill 是静默的**（表现＝退化到「没有域知识」，用户无感、日志无痕）。登记 **R-PROD-39**；责任人：后续扩域的卡 + P4 收口。
2. **设备执行类语义仍未进模型可见面**：`meta_set` / `persona_switch` / `consent_record` / `sync_trigger` 的「在用户设备上生效、服务端只挂起」这条事实，工具 `description` 一字未提，而本卡**刻意没有**为它写 Skill——05j 会把 `meta_set`（可能还有 `persona_switch`）移出设备执行面，那时写下的规则就要跟着改。**建议随 05j 一并补齐**（它是那批语义变动的同一张卡）。责任人：05j / P4 收口。
3. **跨域同义读工具的重叠措辞**（`transaction_summary` 与 `stats_monthly` 都声称适用「这个月花了多少」）在真实抽样里**没有被观察到误选**，因此本卡不动它（「不改工具定义」是职责边界）。若 05g 的准确率实测暴露它，正确处置是改其中一方的 `description`，而不是加一条 Skill 让它兜着。
4. **预载依赖「注入面被收窄」这一可观察量**：05g 落地前，注入面恒为全量，前瞻式命中因此不会发生（懒加载仍生效）。这是刻意的解耦——本卡不 import 域路由，路由落地那天零接线自动生效（显式 `tools=` 的用例/探针同理）。
