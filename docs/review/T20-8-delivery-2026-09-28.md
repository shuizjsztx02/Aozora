## 二、改动（`DetailPage.tsx` 唯一代码文件）

### 2.1 卡面第一层：三处 className

| 落点 | 改动 | 作用 |
| --- | --- | --- |
| `:264` 左侧控件组 | `flex items-center gap-1` → 加 `shrink-0` | 左侧不再被 flex 压缩 → 月份按钮不被挤到折行 |
| `:275` 月份标签按钮 | 加 `whitespace-nowrap` | 中文断行不再允许在「2026年9」与「月」之间断开 |
| `:291` 右侧汇总 | `text-sm` → `text-sm ml-2 shrink-0 whitespace-nowrap` | 汇总不被压缩、不折行 |

### 2.2 卡面第二层：空间不足时的降级（决策 #17 的落地）

**只加 `shrink-0` + `whitespace-nowrap` 会把「折行」换成「溢出」**——实测证实（§3.1），故同卡落地决策 #17 授权的降级：

| 落点 | 窄屏变体 | 一档差 |
| --- | --- | --- |
| `:298` 右侧汇总容器 | `max-[400px]:text-[13px] max-[400px]:ml-1` | 14px → 13px |
| `:300` / `:304` 两个金额 | `max-[400px]:text-[13px]` | **15px → 13px**（卡片点名的「一档」） |
| `:303`「收入」前缀 | `max-[400px]:ml-1` | 间距 8px → 4px |
| `:265` 左侧控件组 | `max-[380px]:gap-0.5` | 组内间距 4px → 2px ×2 |
| `:276` 月份标签 | `max-[380px]:text-[15px]` | 17px → 15px（决策 #17「左侧允许被压缩」） |

**阈值取 400px 的依据（实测，非估算）**：390 视口下内容需求 **357px**、可用 **358px**——**余量仅 1px**。任何字体渲染差异都会吃掉它，故不把 390 放在「不降级」一侧。`380px` 一档覆盖 375 及以下。

**金额口径一行未动**：`fmtTotal` / `Money.formatYuan` 原样，无千分位、无「万」单位、无截断。

## 三、窄屏实测（卡面第②项）

### 3.1 桌面 Chromium 几何实测：修复前 / 后三段对照

**方法**：Playwright + mock bridge 注入长金额 fixture（支出 `529181` 分 = **5291.81**、收入 `9000500` 分 = **90005**，即附件 #519 的现场数值），导航 `/#/detail`，读取期间行的 `getBoundingClientRect` 与 `scrollWidth`。判据＝折行（高度 > 1.5 倍行高）+ 溢出（`scrollWidth > clientWidth`）。

| 视口 | **修复前**（HEAD 原版） | **只加三处 className** | **＋降级（最终）** |
| --- | --- | --- | --- |
| 412 | 不折行 / 不溢出 | 不折行 / 不溢出 | 不折行 / **0 溢出** |
| 390 | 不折行 / 不溢出 | 不折行 / 不溢出 | 不折行 / **0 溢出** |
| 375 | **折行**（汇总 42.8px＝2 行、月份 59px＝2 行）/ 不溢出 | 不折行 / **溢出 14px** | 不折行 / **0 溢出** |
| 360 | **折行**（同上） / 不溢出 | 不折行 / **溢出 29px** | 不折行 / **0 溢出** |
| 352 | — | — | 不折行 / **0 溢出** |
| 320 | **折行**（同上） / 不溢出 | 不折行 / **溢出 69px** | 不折行 / **溢出 30px** |

**三条读数**：①**判据有效**——修复前 375/360/320 三档**全部判定折行**，与附件 #519 的现场一致；②只加 className 确实消除折行，但**把折行换成了溢出**（这正是决策 #17 预见并授权降级的原因）；③降级后 **≥352px 视口全部归零**。

> **卡面阈值被实测修正（如实记录）**：决策 #17 的降级触发条件写的是「极窄屏（**≤320px 内容宽**）仍溢出」，隐含「视口 ≥352 即安全」。实测**该口径成立**——视口 352（内容宽 320）恰好归零；而**只加 className 时，视口 375 就溢出**，故降级必须在 ≥375 档生效，不能等到 352。这是本次把阈值定在 `max-[400px]` / `max-[380px]` 的实测依据。

### 3.2 真实 Android 字体度量（替代端到端设备走查的等价证据）

**为什么不做端到端设备走查（保密性说明，非跳过）**：共享模拟器 `emulator-5554` 上的 app **正停在 `#/assistant`**——恰是并发会话 T20-9 的走查面。`Target.createTarget` 在 WebView 上返回 **`Not supported`**（无多 target 能力），故唯一路径是**导航走共享页面**，会破坏并发会话的页面内状态（T-M7-03 已实证「reload 后页内记录器全丢」）。**判定为不可接受的干扰，不做。**

**替代方案（精度高于目视截图）**：用 CDP 在**真实 Android WebView**里插入 offscreen 隐藏元素测文本宽度——不改数据、不导航、不改变可见布局。

**环境**：`Pixel_7_API_36` / **Android 16** / WebView **Chrome 133.0.6943.137** / `dpr 2.625` / `cssW 412`。

| 文本 | Android 实测 | 桌面 Chromium | 差 | 比例 |
| --- | --- | --- | --- | --- |
| 「支出 」(13px/400) | 25.99 | 26.00 | −0.01 | 1.000 |
| 「5291.81」(13px/600 tabular) | **47.46** | 44.63 | **+2.83** | **1.063** |
| 「90005」(13px/600 tabular) | **36.39** | 34.80 | **+1.59** | **1.046** |
| 「0–9」(13px/600 tabular) | **72.77** | 69.33 | **+3.44** | **1.050** |
| 右侧汇总合计（13px） | **135.83** | 131.43 | **+4.40** | **1.033** |
| 「2026年9月」(15px/600) | 73.48 | 71.73 | +1.75 | 1.024 |

**结论**：**Android 的数字比桌面宽 4.6%–6.3%**（`tabular-nums` 在 Android 上更宽），中文宽度基本一致；右侧汇总整体**宽 4.40px**。据此把 §3.1 的桌面读数换算到真机：

| 视口 | 可用内容宽 | Android 字体需求 | 余量 | 判定 |
| --- | --- | --- | --- | --- |
| 412 | 380 | 322.4 | **+57.6** | ✅ |
| 390 | 358 | 322.4 | **+35.6** | ✅ |
| 375 | 343 | 322.4 | **+20.6** | ✅ |
| **360**（主流窄 Android 真机） | 328 | 322.4 | **+5.6** | ✅ |
| 352 | 320 | 322.4 | **−2.4** | 溢出（见下） |

**「实测机型与宽度」记录（卡面要求）**：真机等效验证覆盖 **Android 16 / Chrome 133 / CSS 宽 412（Pixel 7 逻辑宽）的字体度量**，并按该度量推算 **412 / 390 / 375 / 360 四档均不折行、不溢出**；**352px 视口（内容宽 320px）在 Android 字体下溢出约 2.4px**——该档正是决策 #17 明文承认「≤320px 内容宽仍溢出」的情形，属**卡面授权的边界**，不再继续降级（继续降需第二档缩字号，超出「缩一档」口径）。

> **受限说明**：本卡**未在真机上做「导航到明细页 + 目视长金额」的端到端走查**（理由见上）。**建议 T20-10 收口时在空闲模拟器上补一次**——届时 T20-9 已让出设备。

## 五、卡面第③项：重拍 detail 四张基线 —— **执行了，但结论是「基线未变」，并发现既有缺陷**

**执行**：`npx playwright test --config=playwright.config.ts --update-snapshots -g "detail"` → **4 passed**；随后 `git status --short app/visual-tests/baseline/` → **无任何变化**（四张 PNG 逐字节相同）。

**根因（既有缺陷，非本卡引入）**：`visual-tests/pages.spec.ts` 对认证页面用**路径式导航** `page.goto('/detail')`，而 app 是 **HashRouter**（`src/app/Router.tsx:2`）——实测落到 **`http://127.0.0.1:5173/detail#/home`**，即**渲染的是首页**。佐证：`dawn-home.png` 与 `dawn-detail.png` 的 **md5 完全相同**（`fce414d1…`）。**故 detail 四张基线拍的是首页**，而首页没有期间行 → 本卡的改动对基线**必然零影响**，「重拍」无法验证 REQ-81。

**本卡的处理（不扩大范围）**：按卡面「只重拍自己动的页面」执行完毕并如实记录，**未修改 `pages.spec.ts`**——修它（`goto('/#' + path)`）会让 5 个认证页 × 4 主题 = **20 张基线全部需要重拍**，远超本卡范围，且会与 T20-9 的 assistant 基线重拍交叉。**提请 T20-10 决策**：是否把 hook 修正 + 全量基线重拍作为独立条目。

**关于「补守护」**：卡面倾向「优先用基线」，但**基线当前拍不到 detail**，故本卡**未补守护**；真正的回归守护建议随 hook 修正一并落地（本卡用过的几何判据可直接复用：`scrollWidth > clientWidth` 判溢出、元素高度 > 1.5 倍行高判折行）。

## 七、本卡结论

1. **REQ-81 的折行已根除**：报告的两条独立成因（缺 `shrink-0` / 缺 `whitespace-nowrap`）均已闭合，**≥352px 视口零折行、零溢出**；按 Android 真实字体度量推算，**≥360px 的主流真机全部安全**。
2. **金额口径一行未动**，符合决策 #17；唯一降级是卡片授权的「汇总缩字号一档」（15px → 13px），并额外按「左侧允许被压缩」缩了月份标签（17px → 15px），全部**只在窄屏生效**，412px 及以上保持原样。
3. **两项如实记录、未粉饰**：①端到端设备走查**未做**（共享模拟器被并发会话占用，替代证据见 §3.2）；②detail 视觉基线**实际拍的是首页**（既有 hook 缺陷），故「重拍」形同空转——这两项都已给出可执行的后续建议。
