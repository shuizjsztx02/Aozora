## 三、设计决策（四条，均在卡面既定口径内落地）

### 3.1 分组在组件内做，宿主零改动（决策 #10 的落法）

卡面定死「改共享组件 `CategoryPager` 一处、三个宿主受益」「三个宿主过滤口径不动，仍传扁平全量」。落法：`useMemo` 一次遍历把传入列表拆成 `topLevel` + `childrenOf`（`entry-controls.tsx:35-49`），宫格分页改从 `topLevel` 切片（`:51-58`）。

**这是本卡唯一的口径变化**：分页基数从「扁平全量」改为「一级集合」——10 个一级 + 5 个二级从 2 页变 1 页。这是层级化的直接后果（二级不再占格），不是副作用。

### 3.2 展开态是「派生 + 用户态」的合成，**不用 effect**

```
expandedId = (选中的是二级 && 其父确有子类) ? 其父 : 用户最近点亮的一级
```

三条理由：

1. **「选的是谁的孩子」必须始终看得见**（REQ-76 修复设计 ③）：选中的是二级时，其父**恒展开**，二级面板里那个子项带 active 态，一级格同时点亮。
2. **「已展开时再点＝收起」要求存在一个用户可控的收起态**——纯从选中值派生就永远收不起来。故用 `useState` 记「用户最近点亮的一级」。
3. **两者不冲突**：收起只能由「点一级格」触发，而那必然把选中改回一级——即「选中是二级」与「已收起」不可能同时成立。

选这条的好处是**不需要任何 effect 同步**（也就不会踩 oxlint 的 `react(set-state-in-effect)`）：外部把 `selectedId` 改成某个二级时，父面板当帧即展开。

**切换收支的残留态**：`userExpandedId` 可能在切换后指向已不在列表里的一级——`childrenOf` 查不到即不渲染面板（无副作用）；切回来时展开态恢复，视为状态保留而非缺陷。

### 3.3 孤儿分类按一级渲染（零回归护栏）

`cat.parentId && known.has(cat.parentId)` 才归二级；**父类不在本列表内**的按一级处理。理由：改动前它们在宫格里本来就**可选中**，若直接丢弃，等于让这个分类在选择器里凭空消失（用户再也改不回来）。经查两级的 `kind` 必须一致（`RepositoryCategoryTest.kt:89-95`），故三个宿主按 kind 过滤时不会真的产生孤儿——这是**保行为的防御分支**，已用例钉住。

### 3.4 二级面板的形态

「内嵌容器 + 从属视觉，对齐附件 #151」＋「沿用现有格子样式但置于内嵌容器」（REQ-76 修复设计 ①）→ 落法：`rounded-xl` + `p-2` + glass 底/描边的容器（`entry-controls.tsx:161-167`），内含 `grid-cols-5` 的**同款 `cat-cell`**（`:169-182`，与一级格同一套样式，从属感由容器给出）。**面板置于宫格容器之外**——宫格上的 touch 横滑处理器不覆盖面板，面板上滑动不翻页。

标记用 `▾`（本 App 既有展开语义，见 `EntryChipRow` 的三个 chip），展开时旋转 180°，`position: absolute` 挂在一级格右上角；**只给有子类的一级加**，无子类的一级零变化。

**新增用例清单（`entry-controls.test.tsx`，`describe('CategoryPager — 层级化（T19-5）')`）：**

1. 宫格只排一级；二级不进格；仅带子类的一级有可展开标记；占位仍按一级数补
2. 点带子类的一级 = 选中该一级（**★不下钻**）+ 其二级面板展开
3. 已展开时再点该一级 → 收起（选中值不变，仍是一级）
4. 点二级格 → `onSelect` 收到二级 id，面板保持展开
5. 无子类的一级：点击只选中，不展开（零回归）
6. 受控 `selectedId` 落在二级 → 其一级格 active 且面板默认展开
7. 二级不参与分页：10 个一级 + 2 个二级仍是单页、无指示点
8. 父类不在列表内的孤儿按一级渲染（不凭空消失、仍可选中）

**宿主侧守护用例（`confirmation-card.test.tsx`）：** 「**★一级仍是合法终值**：选带子类的一级不下钻 → 确认后落子就是该一级」——这是**决策 #11 要求的显式守护**，且打在**最强的那一层**（提交给 `onEditCommit` 的 `categoryId` 就是一级 id，不只是组件回调）。
