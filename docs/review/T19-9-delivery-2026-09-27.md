## 四、收口期新发现（两条，均已登记风险册，**均未修**）

### ① ★ agent 车道不注入【用户画像】，且没有任何读工具（P1，**R-PROD-49**）

- **现象**：服务端 `user_profile` 明确含 `{"nickname":"爹","occupation":"地铁司机",…}`，**新开空会话**问「我的职业是什么？」→ AI 答「你之前没在设置里填过职业，所以我这边没有这条信息」。
- **排除性取证**：同会话里 AI 对昵称答「称呼这块是我刚设的」——那是**对话历史**（它自己刚说过）；换成空会话后两个字段都不知道 → 「历史」解释被排除。
- **代码级根因**：`agent.AgentLoop._system_message()` = `_AGENT_SYSTEM_PROMPT` + 日期 + `_render_object_section(ctx)`（**只渲染分类/账户/账本名**）+ 摘要 + 域知识；**`agent.py` 全文 grep 无「画像」/`profile`**。会渲染【用户画像】的 `prompts._render_context_section` 只被 `render_messages_with_context` 调用（**v1 config 车道**，`service.py:269`），设备在线不走它。**并且 `meta` 域只有 `meta_set`（write）一个工具，没有任何读工具**——AI 连「主动查一下」的路都没有。
- **影响**：REQ-74 的**读侧不成立**。「写侧唯一真身」成立、「表单页可见」成立，但画像作为 **AI context 注入源**（`SyncMetaEntity` 注释原话）的本职在设备上为零；卡面第 2 条的验收句正是「再问 AI 的闭环」，**该条实测失败**。
- **未修的理由**：修法要么加常驻【用户画像】段、要么加 `profile_get` 读工具，**两者都改变快路径的 token 基线**，而 T-M7-05h/§7.1 的整套设计（域路由收窄、Skill 按需加载）正是为保住它——「未命中时系统提示逐字相同」是被用例钉住的不变量。需要重新取 token 实测与 SLO 口径，属**设计决策**，不在收口卡范围。

### ② 非记账执行的回执说谎 + 撤销窗污染（**R-PROD-50**）

- **现象（两次命中）**：对话改分类图标 → 界面写「交通分类的图标已经换成 🚗 了。**已记录 1 笔交易**」；对话「以后叫我爹」→「好嘞，以后就叫你爹 👌 **已记录 1 笔交易**」。**两次都没有任何交易被记录**。
- **根因（定位到具体两行）**：服务端回执里的 `transaction_ids` 自 v2 起就是**受影响实体 id** 的通用列表（`service.py:788` 注释明写）；客户端类型也早已叫 `entityIds`——**只有文案与撤销窗仍按「就是交易」用**：`use-assistant.ts` 的自动执行收尾分支把 `已记录 ${ids.length} 笔交易` 写死，同一个数组又赋给 `activeTxIdsRef`。
- **反差点**：这是 T18-3「回执诚实化」的同一主题；T18-9 §已知限制① 已记过它的一个真机实例（当时只当观察），**本卡把根因定位到了具体位置**。
- **未修的理由**：「非记账执行的回执照什么口径显示」是产品决策（与 R-PROD-31 尾卡同族），不在收口卡范围。
