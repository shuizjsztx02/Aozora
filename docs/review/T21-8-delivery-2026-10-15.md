## 二、设计决策与落地

### 2.1 首页入口：条件渲染 + 降级

`loadData` 与既有 `book.list` / `category.list` / `budget.list` / `listSavingsGoals` **并行** `autobook.get_status`，单独 `.catch(() => ({ pendingConfirmCount: 0 }))`——老版本客户端（未升级到 T21-5）或桥失败时归零，**不挡主流程、不崩首页**。

`pendingConfirmCount > 0` 时才渲染入口（决策 #12：「仅当待确认数 > 0 时出现」）。文案：「小贝发现了 N 笔待确认」+「点进去确认或修改，才会计入账本」——**遵守决策 #20 的诚实口径**：不宣传「全自动」、不写「绝不遗漏」。点击跳 `/autobook/captures`。

### 2.2 待确认箱页面：`AutoBookCapturePage.tsx`

**数据**：`autobook.list_captures` 返回的 `AutoBookCaptureData[]`（留痕行 `mergedInto != null` 已被 T21-5 过滤，此处直接渲染）+ `category.list`（供分类选择器与名字匹配）。

**排序**：`pending_confirm` 在前 → `parsing` → `captured` → `failed` → `committed` → `ignored`；同状态按 `postedAt` 倒序。处置过的条目沉底但仍可见（用户能看到自己处理过什么）。

**单卡信息密度**：通道图标（🔍 无障碍 / 🔔 通知）+ 标题（`parsedJson.category` 优先 → `merchantKey` → `sourceApp` → 通道名回落）+ 来源 App · 时间 + 金额（带收支符号 / 颜色）。**徽标行**：
- `confidence < 0.7` → 「AI 拿不太准」（低置信徽标）
- `multiSource = true` → 「已由 N 个来源确认」（L2 合并徽标，决策 #6 的 `multi_source` 派生量）
- `parsedJson.hint === 'possible_duplicate'` → 「可能与另一笔同额账目重复」（L3 提示，**仅展示，不预选合并，也不预选删除**——决策 #6 的「只提示」口径）

**三按钮**：
- ✓ **确认**：`autobook.resolve_capture({ captureId, resolution: 'confirm' })`
- ✎ **修改**：展开编辑面板（收支 chip / 金额 / 分类 select / 备注 / 日期），改完调 `confirm_modified` + `overrides`（`categoryId` / `amountCents` / `type` / `note` / `bizDate` 缺省的沿用解析结果）
- × **忽略**：`autobook.resolve_capture({ captureId, resolution: 'ignore' })`——**不留半成品账目**（T21-5 的 `ignore` 分支零写）

**处置后行为**：按钮 disabled 防连点；`resolve_capture` 完成即 `load()` 重取列表；**编辑面板在改后确认后自动收起**。

**已处置态**：`committed` 显示「已入账」、`ignored` 显示「已忽略」，不再显示操作按钮。

**顶部小结**：`共 N 条，M 条待确认`（M 只计 `pending_confirm`，与首页角标同源）。

**顶部提示**：`status.enabled === false` 时给一行「自动记账未开启」提示，引导用户去设置页——但**历史待确认仍渲染**（用户可能关了开关但仍想处理历史）。

### 2.3 路由

`/autobook/captures` 放在 `/settings/autobook`（T21-7）之后，外层包 `ProtectedRoute` + `AppLayout`（与 `/settings/...` 一致，带底部导航）。

### 2.4 `parsedJson` 字段读取（纯函数，无 LLM）

`parsedCategory` / `parsedAmount` / `parsedType` / `parsedNote` / `parsedBizDate` / `duplicateHint` 全是类型守卫 + 兜底 null——**模型输出不可信**（T21-2 的 `kind` 非法回退、`confidence` clamp、`note` 截 100 字符都已做），但**前端仍要做防御性解析**，避免任何一项坏字段让整卡崩。

`matchCategoryId(categories, name, direction)` 先按「收支方向 + 名字」精确匹配，再退一步只按名字（与 T21-5 的 `resolveCategoryId` 同法，决策 #4.4 已记为已知限制）。

### 2.5 不做什么（再次明确）

- **悬浮窗**：不申请 `SYSTEM_ALERT_WINDOW`——捕获后的即时触达复用 `POST_NOTIFICATIONS`，待确认入口在首页（决策 #4）
- **静默入账**：自动入账的条目（高置信）走既有"立即可见 + 撤销"通道，**不**出现在待确认箱——这是 PR-2「永不产生用户不知情的账目」的兑现
- **预选合并 / 预选删除**：L3 疑似重复**只提示**，不预选（决策 #6）
- **重复处置**：已 `committed` 再确认走 T21-5 的幂等路径（`alreadyResolved: true`），本卡不需要特殊处理
- **空列表文案**：「小贝会在收到支付类通知或你在支付页时自动记录」——**诚实口径**（决策 #20）

### 3.2 用例覆盖

**`AutoBookCapturePage.test.tsx`（15 条）**：

- 自动记账未启用 → 顶部给启用提示（但历史待确认仍渲染）
