## 二、设计决策与落地

### 2.1 `PermissionManager` 扩「设置页授权」形态（决策 #10 三态）

**核心难点**：无障碍服务 / 通知使用权**都不是运行时权限**——`checkSelfPermission` 查不到、`requestPermission` 弹窗也走不到。两者只能：① 用系统 API 查是否启用（`AccessibilityManager.getEnabledAccessibilityServiceList` / `NotificationManagerCompat.getEnabledListenerPackages`），② 跳系统级设置页让用户手动授予（`ACTION_ACCESSIBILITY_SETTINGS` / `ACTION_NOTIFICATION_LISTENER_SETTINGS`）。

**三态判定**：
- `UNAUTHORIZED`：系统当前查不到 + 本地无「曾经启用」记录
- `ENABLED`：系统当前查到（查询时同步把本地 `ever_enabled` 标记置 true，避免下次被停用后回落错态）
- `ENABLED_BUT_DISABLED`：系统当前查不到、但本地 `ever_enabled = true`（用户启用过，后来被系统省电策略或手动停用）

**两个 target 独立**（决策 #10：只授一个也应有可用的一半能力）：本地 ever_enabled 键分两个（`autobook_accessibility_ever_enabled` / `autobook_notification_ever_enabled`），互不干扰。

**`openSettingsAuthTarget`**：跳系统页，`FLAG_ACTIVITY_NEW_TASK`。`ACTION_NOTIFICATION_LISTENER_SETTINGS` 在少数 ROM 上无 Activity 处理时兜底到应用详情页（至少让用户能看到应用条目）。

### 2.2 `AozoraBridge` 改造：统一判定入口

T21-5 在 `AozoraBridge` 内嵌的 `isAccessibilityServiceEnabled` / `isNotificationListenerEnabled` 两个私有方法删除——**统一由 `PermissionManager` 判定**，避免两处实现漂移。这是 T21-5 在 `handleAutoBookGetStatus` 的 TODO 注释里预留的演进路径（`★ T21-7 会把这两条判定收进 PermissionManager 的「设置页授权」形态（含「已授权但服务被停用」的第三态）；届时此处改为调用它，避免两处实现。`）。

**下发 payload 升级**：
- 新字段：`accessibilityStatus` / `notificationStatus`（三态字符串，小写）
- 旧字段 `accessibilityGranted` / `notificationGranted` 保留作兼容（`status === 'enabled'` 时为 true），让任何潜在的旧版消费方不坏
- **桥计数 87 不动**：`autobook.*` 仍 4 条，只是 payload 字段升级

### 2.3 `permissions.openSettings` 扩 `target` 参数（**不改桥计数**）

**决策**：扩展现有命令的 payload，而非新增命令——
- `target` 缺省 `'app'` → 跳应用详情页（保持既有行为，`openAppSettings()`）
- `target = 'accessibility'` → 跳系统无障碍设置页
- `target = 'notification_listener'` → 跳系统通知使用权页

这样**桥计数 87 不动**，无需触发 T21-5 独占的「四处同步」。TS 侧 `openPermissionSettings(target = 'app')` 默认参数让既有调用零改动。

### 2.4 `AutoBookSettingsPage.tsx` 设计

**总开关**：`anyAuthEverGranted`（任一授权非 UNAUTHORIZED）才可用——否则开关开了也不会有任何数据进来。disabled 时给一行提示「请先在下方启用至少一项授权，再打开开关」。

**两类授权各自的态与引导**：`AuthRow` 组件按三态渲染不同徽标（已启用 ✓ / 已授权但停用 ⚠️ / 未授权 ○）与人话文案：
- 无障碍：「在支付 App 处于支付 / 账单页时读取屏幕文本，可拿到商户名与订单号。」
- 通知：「监听微信支付、支付宝、云闪付、银行 App 的支付消息通知，不随 App 改版失效。」

非启用态都渲染「前往系统设置」按钮，点击调 `openPermissionSettings('accessibility' / 'notification_listener')`。

**来源清单**：只读展示内置三项（微信 / 支付宝 / 云闪付，与 T21-3 `NotificationFilter.DEFAULT_SOURCE_PACKAGES` 同源）。**「从已安装应用添加」按钮 disabled** + 标注「后续版本」——桥计数 87 不动的约束下，来源编辑能力必须挂账（见 §五.1）。

**用途说明**：5 条显著披露（读屏幕文本与通知 / 不操作第三方 App / 非支付内容不落库 / 不申请短信权限 / 可随时撤销），**`**` 语法本地渲染成 `<strong>`**。

**今日 / 待确认双计数**：复用 T21-5 `autobook.get_status` 的 `todayCaptureCount` / `pendingConfirmCount`。

**文案红线**（决策 #20）：顶部说明「支付类通知到了、或在支付页上，就会自动记。没记上的可以一键补」；页脚「受系统与应用改版影响，无法保证所有支付都自动记上。漏记的可在首页『待确认』一键补」——**绝不出现「100% 自动」或「绝不遗漏」**。

**`visibilitychange` 监听**：用户从系统设置页返回时触发 `refreshTick + 1`，重新拉 `getAutoBookStatus`——三态可能从 unauthorized → enabled。

### 2.5 不做什么（再次明确）

- **悬浮窗**：不申请 `SYSTEM_ALERT_WINDOW`，捕获后的通知触达在 T21-3 / T21-4 / T21-6 的捕获路径里（本卡零 Android service 改动）
- **来源清单编辑**：挂账（见 §五.1）
- **`MetaWhitelist.KEYS` 扩键**：自动记账开关走 `AutoBookRepository` 自管键（不进白名单，决策 #9），本卡零 meta 改动
- **桥计数 87**：本卡不动，仅 payload 字段升级
- **Room v12 / meta 11 键**：本卡零 schema / meta 改动

## 五、已知限制与挂账（交 T21-9 收口）

1. **来源清单编辑能力挂账**：`AutoBookSettingsPage.tsx` 的「+ 从已安装应用添加」按钮当前 disabled，标注「后续版本」。实现需新增 `autobook.list_user_sources` / `autobook.set_user_sources` 两条桥命令（桥 87 → 89），与决策 #17 的 T21-5 独占冲突——**须待 T21-5 独占解除后**（通常是 T21-9 收口时一并扩）或另起轮次
2. **「捕获后即时通知触达」路径在本卡零实现**：T21-7 卡片清单第 ③ 项「捕获后的即时触达：用已有 POST_NOTIFICATIONS 发『已记一笔 ¥32.00 · 星巴克 · 点击确认』通知」实际上由 **T21-3 / T21-4 / T21-6 的捕获路径**承担（写入 `auto_captures` 时 / 解析后），本卡只负责设置页。**但** `POST_NOTIFICATIONS` 运行时权限的授予引导，本卡也未做——`AutoBookSettingsPage` 不检查 `POST_NOTIFICATIONS` 态。如用户没授予 `POST_NOTIFICATIONS`，捕获后通知不会显示，UX 不完整。**挂账 T21-9 评估是否补**
3. **「已授权但停用」态的判定依赖本地 ever_enabled 标记**：重装应用 / 清数据会丢失此标记 → 第三态回落为 UNAUTHORIZED。UI 文案略有差异（「未授权」vs「已授权但停用」），但**引导跳同一系统页**，功能无损失
4. **未走真机**：两类授权的三态切换 + 跳系统页 + 设置页与桥交互 都只能在真机/模拟器上验，归 T21-9 收口（决策 #19 ①②⑦）
5. **Robolectric 下 `getEnabledAccessibilityServiceList` / `getEnabledListenerPackages` 始终返回空集**：ENABLED 态**无法在 JVM 单测触发**（测试用 ever_enabled 标记间接验 ENABLED_BUT_DISABLED）。ENABLED 真机验收由 T21-9 现场取证
6. **`AutoBookSettingsPage.tsx` oxlint 警告 +1**：`useEffect(() => loadStatus(), [loadStatus])` 触发 `react(set-state-in-effect)` 警告——与项目 30+ 条既有同类警告同 pattern（挂载时加载的标准做法），T21-8 交付记录 §五.2 已登记
