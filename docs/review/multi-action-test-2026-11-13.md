## 三、未达 20/20 的逐条归因

**真实问题（模型遗漏后续动作，4 条）：**

| 用例 | 现象 |
|---|---|
| MA-08 支付宝到账500，再看看余额 | 只记账，没查余额 |
| MA-09 记早饭8块午饭22块，然后告诉我这个月花了多少 | 只批量记账，没统计 |
| MA-10 记一笔奶茶18，看看余额，再查一下预算 | 三动作只做了第一个 |
| MA-20 记一笔宠物粮80，顺便把分类改成宠物 | 只记账，没改分类 |

路由与工具注入都正确（域齐全、无 tool_unavailable）——这是**模型层的行为遗漏**：`deepseek-flash` 在多动作句里倾向只执行第一个写动作。可修方向：系统提示加一条「一句话包含多个动作时必须逐个执行并在回复里交代」（常驻约 +30 tokens/轮），或对多动作轮在收尾前做一次「动作清单核对」。**尚未实施，待决策。**

**用例设计问题（3 条）：** MA-05 / MA-13 / MA-18 是删除/指代类，新 guest 没有任何历史，模型「找不到要删的那笔」是正确行为——测试集应预置历史数据（如先记两笔再删），这是测试集的改进项，不是产品缺陷。

**期望书写错误（1 条）：** MA-14 实际调用 `budget_summary` + `transaction_summary`（行为正确），但期望组写的是 `budget_get/budget_list`。已记录，测试集后续修正。

## 四、由此发现并修复的路由缺口

**MA-18「把今天的早餐和午餐删掉」** 首轮 `matched=false` → 兜底 16 域、24 个工具全量注入。修复（`98d5314`）：删除类词（删掉/删除/删了/去掉）+ 消费品类名词 → transaction 单域；「删除所有账本」仍走 book 域。复测：`routing domains=["transaction"], matched=true`。回归用例 3 条。

## 五、结论与建议

1. 路由与工具激活在两个判据上全绿（20/20、20/20）——M8-17/8-19 的注入面策略在真实多动作输入上成立，没有出现「工具不可用」。
2. 多动作的剩余短板在**模型执行层**（4/20 遗漏后续动作），不在路由层。建议下一步做系统提示强化 + 多动作轮的动作清单核对（可选做 LLM 回执自检）。
3. 测试集补两类改进：删除/编辑类用例预置历史；修正 MA-14 的期望工具名。
