# Aozora · T-M0-10 执行治理与长期规划设计

**状态：** 待评审
**任务卡：** T-M0-10
**变更级别：** L3（影响架构任务依赖、工程门禁与后续 Agent 交接）

## 目标

把已完成的仓库重基线转换为可由不同 Agent 连续执行的生产路线图；在开始功能开发前明确阻塞项、待确认的实施参数、阶段闸门和唯一任务入口。

## 范围

本任务只维护规划与治理文档，不实现客户端、服务端、同步、AI 或基础设施代码。它会：

- 收口 T-M0-09 的完成状态和验证证据。
- 新建一份长期执行规划，列出按依赖排序的任务、交接产物、闸门和外部待办。
- 修复风险登记册与里程碑总览中的过期状态。
- 在 `APP-CONTEXT.md` 中补齐缺失的 `T-M1-05`，并修正使用该编号的依赖关系。

不会改变已确认的 D-PROD-01～D-PROD-11、产品范围、技术栈或数据不变量。

## 执行模型

采用“闸门驱动、单任务交接”的模型。每项任务必须在开始前创建/更新需求卡，明确范围、依赖、影响、回退与验收；完成后提交验证结果、风险变化与下一任务的输入。Agent 不跨越未满足的硬依赖。

```text
M0 收口与外部待办
  ├─ T-M0-10 文档/任务治理
  └─ T-M0-07 基础设施盘点 ─────────────┐
                                         ▼
M1 类型/测试 → 金额日期 → ActionProposal → Room + 本地 NLU
                                         │
                         ┌───────────────┴───────────────┐
                         ▼                               ▼
                  M2 服务端基础                    M3 同步与恢复
                         │                               │
                         └───────────────┬───────────────┘
                                         ▼
                              M4 AI、原生与完整体验
                                         ▼
                              M5 安全、质量与内测
                                         ▼
                                M6 生产发布与观察
```
